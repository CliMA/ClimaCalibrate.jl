Calibration report

ClimaCalibrate provides utilities for reporting the state of each iteration of a calibration. This is implemented with a CalibrationReport which is built from AbstractReporters such as

  • WalltimeReporter for reporting the walltime information,
  • TimestepReporter for reporting the timesteps taken,
  • ErrorReporter for reporting the error metrics,
  • ParameterReporter for reporting the parameter trajectory,
  • EnsembleReporter for reporting the state of the ensemble,
  • and ObservationReporter for reporting the observations.

Example

You can build a CalibrationReport by passing a tuple of AbstractReporters to the reporters keyword argument.

import ClimaCalibrate.Report as Report

reporters = (
    # Estimate the remaining walltime for a calibration of 10 iterations
    Report.WalltimeReporter(10),
    Report.TimestepReporter(),
    Report.ErrorReporter(; error_metrics = ["loss", "unweighted_loss"]),
    Report.ParameterReporter(),
    Report.EnsembleReporter(),
    Report.ObservationReporter(),
)
calibration_report = Report.CalibrationReport(; reporters)

Events

A calibration logs a report at each of these AbstractEvents:

  • CalibrationStart: before the first iteration that runs, including when a calibration is resumed,
  • IterationStart: at the start of each iteration, before the forward models run,
  • IterationEnd: at the end of each iteration, after the EnsembleKalmanProcess is updated,
  • CalibrationEnd: after the last iteration.

For a calibration of n iterations, the events happen in this order:

CalibrationStart(1)
IterationStart(1), IterationEnd(1)
IterationStart(2), IterationEnd(2)
⋮
IterationStart(n), IterationEnd(n)
CalibrationEnd(n)

IterationEnd happens at the end of every iteration, while CalibrationEnd happens once, after the last iteration. Use IterationEnd to report on each iteration, such as its error, and CalibrationEnd to summarize the whole calibration.

The order changes in these cases:

  • When a calibration is resumed, it starts at the first iteration that is not completed, so the first event is CalibrationStart(k) for that iteration k.
  • When the scheduler terminates the calibration in iteration i, the EnsembleKalmanProcess is not updated, so there is no IterationEnd(i) and the last event is CalibrationEnd(i - 1).

Each reporter decides which events it reports on. A reporter that prints nothing for an event is left out of the report of that event, and if every reporter prints nothing, nothing is logged.

Implementing your own AbstractReporter

To write your own reporter, subtype AbstractReporter and add a method to report, and optionally to title. The method below reports at the end of each iteration.

import ClimaCalibrate.Report as Report

struct YourReporter <: Report.AbstractReporter end

function Report.report(
    io::IO,
    reporter::YourReporter,
    event::Report.IterationEnd,
    context::Report.ReportContext,
)
    println(io, "Your report for iteration $(event.iteration)")
end

# Optional to implement
Report.title(reporter::YourReporter) = "Your section title"

calibration_report = Report.CalibrationReport(;
    reporters = (Report.ErrorReporter(), YourReporter()),
)

The type of event decides when a section is shown. The method above is for IterationEnd, so its section is shown at the end of each iteration. To show a section at another event, such as a summary at CalibrationEnd, add a method for that event, and to show it at every event, leave the type of event unspecified.

The sections of the report are in the same order as the reporters passed to CalibrationReport.

To format a section like the built-in reporters, pass a vector of label => value pairs with string labels to print_aligned. It prints each pair as label: value and pads the labels so that the values line up.

How are reports generated?

The arguments to report are

  • io: Where to write the section. Write to io with print or println instead of logging with @info or printing to stdout, so that the section is part of the report.
  • event: The AbstractEvent that is reported.
  • context: The ReportContext of the calibration, which holds
    • ekp: The EnsembleKalmanProcess. At CalibrationStart and IterationStart, it is the process before the iteration runs. At IterationEnd and CalibrationEnd, it is the process after the update of the last iteration.
    • prior: The ParameterDistribution of the calibration.
    • output_dir: Directory to write logs or plots to.

CalibrationReport prints the title of the section and indents the lines below it, so a reporter should not print its own title or indent its lines.
